# Prompts

在 LangChain 中，**提示词模板（Prompt Template）** 不仅仅是一段文字，它是一个**可重复使用的“生产逻辑”**。它的本质是将**不变的指令（System Prompt）**与**变化的变量（User Input/Context）**解耦。

------

## 1. 什么是提示词模板？

如果你直接给 LLM 发送字符串，那是“死”的。模板则是“活”的，它通过 `{variable}` 占位符，允许你在运行时动态注入数据（比如从数据库检索出的日志、用户的提问等）。

------

## 2. LangChain 中常见的模板类型

#### ① `PromptTemplate` (最基础型)

适用于纯文本模型。它简单地将字符串和变量组合。

- **用法**：`PromptTemplate.from_template("帮我分析这个报错：{error_log}")`
- **场景**：简单的脚本生成、基础问答。

#### ② `ChatPromptTemplate` (对话型 - 你的项目正在用的)

这是为聊天模型（如 Qwen, GPT-4）设计的。它将消息分为不同的**角色**，这对引导 AI 的行为至关重要。

- **结构**：由 `SystemMessage`（设定规则）、`HumanMessage`（用户提问）、`AIMessage`（AI 的历史回复）组成。
- **场景**：构建像你现在这样的 AIOps 助手，因为它需要区分“你是专家”和“我是用户”。

#### ③ `FewShotPromptTemplate` (少样本学习型)

这是**提升 AI 逻辑能力**的神器。你在模板里先给 AI 演示 2-3 个“问题 -> 思考 -> 答案”的例子，再让它回答新问题。

- **场景**：当你发现 Qwen 总是乱写 K8s 命令时，你先在模板里写两个标准的排障范例，它就会模仿你的风格。

#### ④ `MessagesPlaceholder` (动态历史占位符)

这是一个特殊的模板组件，专门用于处理**对话记忆（Memory）**。

- **功能**：它会在 Prompt 的特定位置预留空间，让 `RunnableWithMessageHistory` 把成串的历史记录“整堆”塞进去。

------

## 3. AIOps 实战中的模板分层

在你的模块化架构 `core/prompts.py` 中，我建议你这样组织：

Python

```
# core/prompts.py
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder

# 1. 纯指令部分（设定专家的边界）
SYSTEM_INSTRUCTION = "你是一个分布式系统专家，擅长 Kafka 和 K8s。"

# 2. 组合模板
aiops_prompt = ChatPromptTemplate.from_messages([
    ("system", SYSTEM_INSTRUCTION),
    # 使用占位符来接收多轮对话历史
    MessagesPlaceholder(variable_name="chat_history"), 
    ("human", "背景信息：{context}\n\n我的问题：{input}")
])
```

------

## 4. 为什么要区分这么多模板？

- **解耦**：如果你想把“中文专家”换成“英文专家”，你只需要改 System 模板，不需要动业务代码。
- **省钱（Token 优化）**：通过合理的模板设计，可以减少废话，让 AI 直接输出命令，节省 API 消耗。
- **稳定性**：模板可以强制 AI 遵循特定格式（如 JSON），方便你的后端程序解析 AI 的输出。

## 进阶方向

你现在的模板是 **Zero-Shot（零样本）**，即直接问。

**你想试试把 `FewShotPromptTemplate` 加进去吗？**

比如在你的知识库里，针对“内存溢出”有一套标准的 SRE 操作流程，我们可以把这个流程作为 Example 喂给模板。这样以后只要遇到类似问题，AI 甚至不用检索知识库，就能精准输出你公司的标准操作指令。你要试试看代码怎么写吗？
