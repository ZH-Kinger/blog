# KV Cache这是什么

ZH-Kinger，这是一个非常硬核且高频的面试考点！简单来说，**KV Cache 是大模型推理时的“草稿本”**。

在大模型生成文本时，它是**一个字一个字**往外吐的。如果没有 KV Cache，大模型每吐一个新字，都要把前面所有的字重新计算一遍，这太浪费时间了。

------

### 1. 为什么需要 KV Cache？（核心原理）

大模型基于 **Transformer** 架构，核心是 **Self-Attention（自注意力机制）**。

- **计算过程**：为了生成第 $n$ 个字，模型需要计算这个字与前面 $n-1$ 个字的关系。
- **痛点**：在生成第 $n+1$ 个字时，前 $n$ 个字的中间计算结果（即 **Key** 和 **Value** 向量）其实和上一步是一模一样的。
- **解决方案**：把这些中间结果存起来，下次直接用，不再重复计算。这就是 **KV Cache**。

> **比喻**：就像你在读长篇小说，每读一页都要从第一页开始重读一遍（无 Cache），还是你拿个书签记下前面的剧情，直接往后读（有 Cache）。

------

### 2. KV Cache 带来的“副作用”：显存杀手

虽然它省了计算量（CPU/GPU 计算耗时），但它极其**吃显存（VRAM）**。

#### 显存占用计算公式：

$$Total\_Bytes = 2 \times layers \times heads \times head\_dim \times seq\_len \times batch \times precision$$

- **2**：代表 Key 和 Value 两个矩阵。
- **Precision**：如果是 FP16，就是 2 字节。
- **例子**：以 Llama-7B 为例，当上下文长度达到 4k，Batch 为 1 时，KV Cache 就要占掉约 **1GB** 显存。如果 Batch 变大，显存会迅速炸裂。

------

### 3. 这和 vLLM 有什么关系？（进阶面试点）

你在简历里提到 **vLLM**，面试官一定会追问：**“vLLM 是如何优化 KV Cache 的？”**

你要提到 **PagedAttention**：

- **传统方案**：给每个请求分配**连续**的显存空间。但模型不知道用户会聊多久，只能按最大的上下文（如 32k）预留，导致大量显存闲置（碎片化严重）。
- **vLLM 方案**：像操作系统的**“虚拟内存分页”**一样，把 KV Cache 拆成一小块一小块的“页（Pages）”。
  - **动态分配**：用到多少分配多少，不连续也没关系。
  - **零碎片**：显存利用率从 60% 提升到 90%+，让同一张显卡能跑的并发量（Batch Size）提升了数倍。
