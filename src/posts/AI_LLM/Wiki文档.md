# Wiki文档

在 IT 和运维（AIOps）领域，**Wiki 文档** 就像是一个团队的“**共享大脑**”。

它是一个允许团队成员共同创建、编辑和链接内容的**知识库平台**。对于你正在开发的分布式智能日志分析平台，Wiki 是 RAG 知识库最核心的“喂料”来源。

------

## 1. Wiki 的核心特征：协作与链接

- **人人可编辑**：不像传统的 Word 文档发来发去，Wiki 只要有权限，谁发现报错谁就能上去更新解决方案。
- **超链接结构**：文档之间不是孤立的。比如在“K8s 部署指南”里，可以直接链接到“常见网络故障处理”。
- **版本控制**：你可以看到谁在什么时候改了哪行字，这在排查“谁动了我的配置”时非常有用。

------

## 2. 为什么你的 AIOps 项目离不开 Wiki？

你现在的 `data/` 目录下放的是 `.txt` 文件，但在真实企业中，你的 **RAG 知识库** 通常是直接对接 Wiki 的：

- **标准操作程序 (SOP)**：当系统报警时，AI 会去 Wiki 搜：“公司规定的 502 错误标准处理流程是什么？”
- **故障复盘记录 (Post-mortem)**：以前发生的故障，大拿们写的排障心得都存在 Wiki 里。AI 学习了这些，就能像老员工一样回答问题。
- **资产配置信息**：服务器 IP、中间件版本、域名对应关系等，通常也维护在 Wiki 页面上。

------

## 3. 常见的 Wiki 工具（你以后可能会对接的）

如果你要在简历里写 AIOps 经验，了解这些工具会很专业：

| **工具名称**             | **场景**      | **特点**                                              |
| ------------------------ | ------------- | ----------------------------------------------------- |
| **Confluence**           | 企业最主流    | 功能极其强大，大厂标配，支持复杂的权限管理。          |
| **Notion**               | 创业公司/个人 | 界面漂亮，支持数据库功能，非常适合做知识整理。        |
| **Wiki.js / Docusaurus** | 开源/技术文档 | 适合程序员，支持用 **Markdown** 编写，能和 Git 联动。 |
| **语雀 / 飞书文档**      | 国内常用      | 在线协作非常顺滑，API 接口丰富，方便 LangChain 调用。 |

------

## 4. 它是如何变成你的“向量”的？

在你的项目流程中，Wiki 的角色如下：

1. **导出**：通过 API 把 Wiki 页面下载成 Markdown 或 HTML。
2. **切分**：LangChain 把长篇大论的 Wiki 拆成 500 字的小段。
3. **向量化**：用你现在的 `text2vec` 模型转成数字。
4. **存储**：存进 **ChromaDB**。
