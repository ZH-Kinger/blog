在 IT 系统和软件开发中，日志级别（Log Levels）是对信息**严重程度**的分类。它能帮助开发者在海量信息中快速过滤出关键问题。

目前业界最通用的标准是基于 **RFC 5424**（Syslog 标准）定义的 8 个级别，但在一般的应用开发（如 Python Flask、Java Spring、Log4j）中，常用的主要是以下 5 到 6 种。

### 2. 特殊级别

除了上述五个，还有两个控制级别的开关：


- **TRACE**：比 DEBUG 更细，通常记录每一步代码的执行流，甚至是方法进入/退出。
- **ALL**：开启所有级别的日志。
- **OFF**：关闭所有日志输出。
<hr id="pX4xO" class="ne-hr">
### 3. 日志的“向上兼容”原则

日志系统通常遵循一个规则：**一旦你设置了某个级别，系统会记录该级别及以上的所有日志。**

**举个例子：**


- 如果你设置级别为 **INFO**，那么 INFO、WARN、ERROR、FATAL 都会被记录，但 DEBUG 和 TRACE 会被过滤掉。
- 如果你在生产环境由于硬盘告急想减少日志，可以将级别调高至 **ERROR**，此时 INFO 和 WARN 都不会再打印。
<hr id="JVHfE" class="ne-hr">
### 4. 最佳实践提示


- **生产环境禁止 DEBUG**：DEBUG 日志量极大，会迅速占满磁盘并严重拖慢系统性能（因为写磁盘是耗时操作）。
- **动态调整**：成熟的系统（如 Spring Boot 或 Flask）支持在不重启服务的情况下，通过接口动态修改日志级别，方便在线调试。
- **结构化日志**：建议使用 JSON 格式记录日志，方便后续配合 **ELK**（Elasticsearch, Logstash, Kibana）进行检索和可视化分析。
